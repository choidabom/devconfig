# 사용자 전역 지침

## 아티팩트(HTML 페이지) 글자 레이아웃

- 글자 폭을 따로 제한하지 않는다. 문단·리드에 `max-width: 65ch` 같은 글자 폭 제한을 두지 않고 바깥 래퍼 폭만 쓴다.
- 표에 `min-width: 640px` 같은 최소 폭을 걸지 않는다. 표는 `width: 100%`만 둔다. `min-width: 0`(축소 허용)은 괜찮다.
- 글자가 단어 중간에서 잘려 보이지 않게 한다.
  - body에 `word-break: keep-all; overflow-wrap: break-word;`를 둔다. 한글이 "입니 / 다"처럼 음절 단위로 끊기지 않게 하기 위해서다.
  - 문장 속 인라인 `code`는 `white-space: nowrap`으로 둔다. "x-field- / groups"처럼 하이픈에서 끊기지 않게 하기 위해서다.
  - 표 셀 안의 code나 긴 식별자(모델명, 경로) 셀만 `overflow-wrap: anywhere`를 허용한다.
- 짧은 상태 뱃지 정도만 `white-space: nowrap`을 허용한다.

## 설명 방식

- 비유를 쓰지 않는다. "장부", "창고" 같은 생활 비유로 개념을 치환하지 말고 정확한 용어(state, provider, distribution 등)를 그대로 쓴다.
- 어려운 용어는 비유 대신 정의로 푼다. 그것이 무엇인지, 어디에 있는지, 어떤 명령이 읽고 쓰는지를 한두 문장으로 적는다.
- 쉽게 설명해 달라는 요청은 "문장을 짧게, 단계를 나눠서" 라는 뜻이다. 용어를 바꾸라는 뜻이 아니다.
- 비유적인 단어도 쓰지 않는다. 문서, 아티팩트, 채팅 답변, 슬랙 초안 전부 해당한다. 동작은 그 동작을 뜻하는 동사로만 적는다.
  - 금지 예와 대체어: 재료 → 값·입력, 증상 → 개별 문제, 조용히 빠진다 → 적용되지 않고 오류도 나지 않는다, 메운다 → 처리한다, 따라온다 → 필요하다, 사라진다 → 제외된다, 새다 → 노출된다, 깨진다 → 잘못 나뉜다·실패한다, 신호 → 근거, 소유 → 관리, 한 벌 → 하나·한 종류, 끈다·켠다 → 비활성화한다·활성화한다, 붙인다 → 추가한다, 주인 → 관리 주체, 쥐고 있다 → 가지고 있다, 살아난다 → 다시 동작한다, 뗀다 → 제거한다, 끼운다 → 적용한다, 이긴다 → 우선한다, 구멍 → 누락·미처리.
  - 산출 직전 위 단어들을 grep 으로 훑어 0건인지 확인한다. 아티팩트는 `<main>` 이후 본문만 검사한다.

## 문장 부호

- em-dash(U+2014)를 쓰지 않는다. 채팅 답변, 문서, 아티팩트, 코드 주석, 커밋, PR 전부 해당한다.
  - 제목이나 라벨에서 em-dash 로 잇던 "A, B" 구조는 `A: B` 로 쓴다.
  - 병렬 나열은 가운뎃점 `·` 으로 쓴다.
  - 문장 중간 삽입구는 마침표로 문장을 나누거나 쉼표로 쓴다.
  - 표의 빈칸 표시는 `없음` 으로 쓴다.
- en dash(`–`)는 숫자 범위에만 쓴다. 이 규칙의 대상이 아니다.
- 산출 직전 em-dash 개수를 grep 으로 세어 0인지 확인한다.

## 작업 번호 표기

- 작업계획서 단계 코드(`W-1`, `S-2`, `Phase 3` 등)와 이슈 좌표(`repo#1234 W-1`, `로드맵 13` 등)를 다음 위치에 넣지 않는다.
  - 코드 주석
  - 테스트 `describe`/`it` 이름. 스냅샷 키로 굳는다.
  - 커밋 메시지
  - PR 제목과 본문
- 사용자에게 보고할 때도 단계 코드 대신 그 단계가 하는 일로 부른다. 예를 들어 "W-1" 대신 "규칙 판정 회귀 테스트" 라고 쓴다.
- 주석은 코드가 왜 그렇게 있는지만 적는다. 어느 작업에서 왔는지는 git log 와 PR 이 담는다.
- PR 본문에는 관련 이슈 링크 하나만 두고, 변경은 무엇을 했는지로 적는다.
- 예외는 작업계획서 문서 자체와 그 계획을 추적하는 이슈 본문이다.
- 남이 쓴 기존 주석의 번호는 건드리지 않는다.
- 주석·테스트 이름·커밋·PR 초안을 쓴 직후 `W-[0-9]|S-[0-9]|Phase [0-9]` 와 비공개 지침의 이슈 좌표 패턴으로 내가 추가한 줄을 검사한다.
